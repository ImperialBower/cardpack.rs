## 2026-07-25
* **YAML deck serialization (EPIC-03).** Every deck now round-trips `deck → YAML → deck` under the existing `yaml` feature: a self-describing `DeckYaml` envelope (`version`/`name`/`fluent_deck_key`/`count`/`cards`), a `YamlDecked` blanket trait over `DeckedBase` so consumer decks get it free, and symmetric `to_yaml`/`from_yaml` on `DeckKind` (registry path) and `Pile<T>` (instance path, order-preserving). The crate previously had a YAML read path and no write path. [Extension playbook](decks/extending-decks.md) and [feature flags](architecture/feature-flags.md) updated.
* **Decision**: the envelope **adds** a format rather than replacing one — `DeckYaml::from_yaml` sniffs document shape and keeps the legacy bare-sequence branch, because `razz.yaml` is a bare sequence embedded via `include_str!` at build time. Deleting the "duplicate" reader compiles, passes the envelope tests, and breaks `Razz` into a silent empty deck. New [envelope decision](decisions/yaml-envelope-format.md).
* **Semver**: `CardError` is now `#[non_exhaustive]`, following the `DeckKind` precedent. Six `yaml`-gated variants were added (`YamlCountMismatch`, `YamlDeckMismatch`, `YamlUnknownDeck`, `YamlEmptyDeck`, `YamlForeignCard`, `YamlMalformed`); `cargo semver-checks` confirms the attribute itself is major. Exhaustive downstream matching was never feature-portable anyway, since those variants vanish without `yaml`.
* **Testing**: three integration layers under `tests/` — round-trip (incl. a seeded `proptest`), byte-level golden fixtures generated by `examples/yaml_decks.rs` via `make yaml-fixtures`, and a negative suite whose headline case pins `razz_bad.yml` as well-formed-but-wrong ([build and test](workflows/build-and-test.md)).
* **Prelude**: `Tiny` is re-exported like every other deck; `DeckYaml` and `YamlDecked` are re-exported under `yaml`.

## 2026-07-23
* **Examples flag-free — via a cargo alias, after reverting a self dev-dependency.** First attempt added `cardpack = { path = ".", features = ["full", "funky"] }` as a dev-dep; it broke `cargo deny check bans` in the `kernel-purity` job, because the dev-dep feature-activates `full`+`funky` on cardpack's own node in `cargo metadata`'s feature-unified resolve, so `colored`/`serde_norway`/`fluent-templates` appear as **normal** deps of the kernel. Neither `--exclude-dev`, `[graph] exclude-dev`, nor `no-default-features` suppresses it (`cargo tree --edges normal` stays clean the whole time — that divergence is the trap). Replaced with an `[alias] ex = "run --features full,funky --example"` in `.cargo/config.toml`, so `cargo ex <x>` needs no flags and the dependency graph is untouched. Restored the host `test --no-default-features --lib` and `build --no-default-features --examples` CI steps, which are meaningful again. New [decision](decisions/examples-flag-free-alias.md) (supersedes the deleted `examples-self-dev-dependency.md`); [feature flags](architecture/feature-flags.md) gotcha rewritten.
* **Feature graph**: `funky` now implies `serde` (`funky = ["std", "serde"]`) — the `funky/types/*` files use serde unconditionally, so `--features funky` alone left `serde` unlinked and the `buffoon`/`funky_tour` examples failed to compile ([feature flags](architecture/feature-flags.md), [funky engine](architecture/funky-engine.md)).
* **Decks**: Added Mughal (96) and Dashavatara (120) Ganjifa decks — [deck catalog](decks/deck-catalog.md) now covers 14 kinds; [localization](architecture/localization.md) gains the `mughal`/`dashavatara` fluent bases (EPIC-02).
* **Decision**: DeckKind is now #[non_exhaustive] and the crate bumped to 0.9.0 — adding enum variants was semver-major vs 0.8.1; future deck additions become non-breaking ([deck catalog](decks/deck-catalog.md)).
