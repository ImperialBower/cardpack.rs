# Blooper Report — General — 2026-08-15

An affectionate roast of old cardpack.rs code, dug up from git history.

## 1. A field named `consummables` — worst one

**Version:** commit `740eb9c` ("board"), March 2025

```rust
pub struct Board {
    pub deck: BuffoonPile,
    pub in_hand: BuffoonPile,
    pub played: BuffoonPile,
    pub consummables: BuffoonCard,   // typo, AND wrong type
    pub jokers: BuffoonCard,          // should hold many, not one
}
```

Two mistakes stacked: "consummables" instead of "consumables" (typo), and both
fields typed as a single `BuffoonCard` when a board obviously holds many
consumables and many jokers.

**The fix:** current `src/funky/types/board.rs` has
`pub consumables: BuffoonPile` and `pub jokers: BuffoonPile` — spelled right,
and typed as collections.

## 2. A whole file that talks to itself

**Version:** `src/funky/types/fpips.rs`, added in commit `eb5b337`
("let us get funky"), March 2025

The file had a method named `f_it()`, plus doc comments admitting the struct
had a dead field ("I created this out of habit... Removing it for now") and
calling out its own `Default` impl as an AI-suggested pattern the author
didn't trust.

**The fix:** the file was deleted outright in commit `107b375`, titled
"fpips.rs is retired. Small, clean, and everything's green." The author
caught this one himself.

## 3. `.iter().enumerate()` — then threw the index away

**Version:** v0.3.0

```rust
for (_, suit) in suits.iter().enumerate() {
    for (_, rank) in ranks.iter().enumerate() {
        self.add(Card::new_from_structs(rank.clone(), suit.clone()));
    }
}
```

`enumerate()` numbers each item — pairs it with its position (0, 1, 2...).
Here the number (`_`) was thrown away every time. Plain `.iter()` does the
same job with less code.

**The fix:** gone from current deck-building code.

## Still outstanding

None — all 3 patterns above are fixed in the current tree. 🎉
