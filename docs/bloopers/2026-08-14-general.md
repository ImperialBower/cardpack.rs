# Blooper Report — General — 2026-08-14

An affectionate roast of early cardpack.rs code, dug up from git history.

## 1. Bad Option handling — worst one

**Version:** v0.3.0

Old code checked an `Option` twice: once inside a `match`, then called
`.unwrap()` on it again. Unsafe, and messy.

**The fix:** current code uses the `?` operator, which checks once.
Fixed in v0.4.5.

## 2. Extra trait bound that did nothing

**Version:** v0.3.0 era

Old code put a `Clone` trait bound on `new()` functions that never
actually used `Clone`. Dead weight.

**The fix:** dropped by v0.4.10.

## 3. Format inside a format

**Version:** early era

```rust
print!("...", format!("{}", lang))
```

Converts text to text twice for no reason.

**The fix:** gone from current code.

## 4. Print statements stuck inside the library

Old code had a `demo()` function that always printed to stdout, with
no way to turn it off.

**The fix:** current code takes a `verbose: bool` switch.

## 5. Silenced a real Clippy warning instead of fixing it

Old code got a Clippy lint about poor iterator usage and just
suppressed the warning instead of fixing the underlying code.

**The fix:** gone from current code.

## Still outstanding

None — all 5 patterns above are fixed in the current tree. 🎉
